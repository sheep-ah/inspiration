# 阶段 5（应用内更新）——进行中

任务书 §4 阶段 5 要求：查看当前版本、检查最新稳定正式版本、显示更新说明、下载对应平台安装包、显示下载进度、
校验文件完整性与发布来源、失败后重试、按平台要求完成更新或引导用户安装、更新后验证应用可启动且模板数据保留。

## 1. 已完成

### 1.1 更新器（`internal/updater`）

| 能力 | 实现要点 |
|---|---|
| 检查更新 | 只访问配置仓库的 `releases/latest`；**拒绝 draft / prerelease**；标签格式严格校验（`vX.Y.Z`） |
| 版本比较 | 支持 `v` 前缀、缺失段按 0、预发布后缀（`-rc.1` < 正式版），非数字按 0 处理避免误判 |
| 资产选择 | 按 `runtime.GOOS/GOARCH` 精确匹配：Windows → `_windows_amd64_setup.exe`（回退 portable）；macOS → `_darwin_<arch>.zip`（回退 dmg）；平台无资产时如实提示并给发布页链接 |
| 下载 | 进度回调、600 MB 上限、写入失败/中断即删除临时文件 |
| 来源校验 | **仅允许 HTTPS + github.com / objects.githubusercontent.com / release-assets.githubusercontent.com**，防止被引导到第三方站点 |
| 完整性校验 | `checksums.txt`（发布产物）→ sha256 比对；**校验失败立即删除文件并拒绝安装**；缺少校验和也拒绝 |
| 失败可重试 | 下载失败只删临时文件，不影响当前版本；界面提示可重试 |

### 1.2 按平台安装

| 平台 | 方式 | 关键保障 |
|---|---|---|
| macOS | **整包替换 `.app`**（不改包内文件，避免破坏签名） | 替换前把旧版本重命名为 `.backup-<时间戳>`；新版本就位失败自动回滚；校验 `Info.plist` 与可执行文件存在且可执行；保留备份 7 天自动清理；写脚本延后重启；**不触碰用户数据目录** |
| Windows | 批处理脚本等待进程退出后执行：NSIS 安装包 `setup.exe /S` 静默安装，或便携版覆盖 exe | Windows 会锁定运行中的 exe，因此不能在进程内自我覆盖；脚本以 DETACHED_PROCESS 启动，安装后自动重启应用 |
| 其他平台 | 明确提示"暂不支持应用内更新，请前往发布页手动下载" | 不静默失败 |

### 1.3 应用与界面

- 绑定：`CheckUpdate` / `DownloadUpdate`（`update:progress` 事件，200 ms 限流）/ `ApplyUpdate`（需要重启时自动退出应用）/
  `OpenReleasePage`（只允许打开 `https://github.com/` 链接）/ `AutoCheckUpdate` / `SetAutoCheckUpdate`
- 关于页新增：检查更新按钮、上次检查时间、新版本说明（含 Release body 渲染）、下载进度条、
  「下载并更新」与「前往发布页」、「启动时自动检查更新」开关（**默认关闭**，符合"除检查更新外不发网络请求"）
- 界面实测（桩数据）：检查后显示"发现新版本 v0.2.0：0.1.0 → 0.2.0"、发布时间、更新说明；
  收到进度事件后显示"正在下载更新包… 2.3 MB / 4.9 MB（46%）"

### 1.4 测试

`internal/updater` 共 20 个用例，全部离线可跑（`httptest` 假 GitHub）：

- 版本比较（13 组，含预发布）、`IsNewer`、标签校验（宽松输入全部拒绝）
- 资产选择（三平台 + 缺 zip 回退 + 平台无资产报错）
- 检查更新：已是最新、发现新版并带上说明、拒绝 draft/prerelease、平台无资产提示
- 下载：进度回调、sha256 计算与校验、非可信来源拒绝、checksums 解析与获取
- macOS 安装：整包替换成功（新版本就位 + 可执行权限保留 + 旧版本备份）、
  坏 zip / 无 .app / 结构不完整三种失败路径都不破坏当前版本且不产生备份
- 跨平台：解压/校验/备份清理这些与平台无关的逻辑有独立用例，在 Linux CI 上也会运行
